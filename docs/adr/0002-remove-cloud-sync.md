# 移除云同步，回归纯本地应用

**状态**：已接受（取代 [ADR-0001](./0001-sync-engine.md)）

## 背景

ADR-0001 建立了 SyncEngine/SyncPort 云同步架构，后端为 Supabase 匿名登录。但匿名 `user_id` 是每个浏览器随机生成的：数据确实在推往云端，却永远无法在另一台设备找回；而同一浏览器内 localStorage 本就持有全部数据。云同步对用户可感知的价值为零，纯成本（每次改动后的写放大、启动网络请求、崩溃面、依赖与密钥维护）。跨设备迁移由 JSON 导入导出承担。

## 决策

移除整个云集成：Supabase 服务层（`src/services/supabase/`）、同步引擎（`syncEngine.js`/`syncPort.js`/`stateMerge.js`）、分享码、埋点与异常上报、`@supabase/supabase-js` 依赖、`supabase/` 目录及相关环境变量。应用回归纯本地（localStorage）+ JSON 导入导出。

## 考虑过的选项

1. **保留分享码**（云集成中唯一有跨设备价值的部分）——否决：为单一功能保留整套后端、密钥与数据库不值得；JSON 导入导出已覆盖迁移需求。
2. **用 URL 链接分享替代分享码**——否决：不想为此新增任何分享机制。
3. **维持现状**——否决：见背景。

## 后果

- `Grade`/`Profile` 中的 `updatedAt` 字段失去同步合并用途，仅为存储格式兼容而保留。
- 若未来重新引入云同步，需从零设计（且必须先解决身份体系，而不是匿名登录）。
